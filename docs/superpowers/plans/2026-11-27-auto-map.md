# Auto-map by file name Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adding samples named like `Ab3P.wav` / `Ab3MF.wav` maps each to its note's key range and splits velocity between a note's dynamic layers.

**Architecture:** notes.c learns to read a note with a dynamic suffix and the dynamic itself; multi.c gets one function that remaps every named sample in the list; plugin.c's take_samples calls it after an add and appends the summary to the status.

**Tech Stack:** C (MSVC), pytest + ctypes, tests/host.exe gui scripts.

**Spec:** docs/superpowers/specs/2026-11-27-auto-map-design.md

## Global Constraints

- Dynamics, case-insensitive, softest first: ppp pp p mp mf f ff fff (ranks 1..8); no dynamic ranks as mf (5).
- Layer k of L on one note: velocity 1 + k*127/L .. (k+1)*127/L (integer division).
- Status copy: "Ready: N samples, mapped to M notes" plus " in up to L velocity layers" when L > 1.
- Never put Finnish Forest Percussion samples in tests (generated tones only).

## Review Focus

- `Bb4.wav` (flat, no dynamic) still reads as Bb4, and `Take2.wav`, `C3then.wav` still read as no note.
- A standalone `F` word with no note is not a note (a dynamic only counts beside a note).
- Adding an unnamed sample (`Kick.wav`) to a mapped list leaves the map alone.
- Two adjacent notes (C4, C#4) share no key; an odd gap splits with the lower note taking the middle key.
- Missing samples (file gone) with note names still map by their path.
